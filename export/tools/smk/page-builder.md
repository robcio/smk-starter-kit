# Core Page Builder — C10.6

`/demo-core` is a separate neutral demonstration entry. Home and its content are preserved. Page Builder uses Replicator with at most20 rows (including disabled), one optional Hero first among visible rows, Rich Text/Bard and CTA. Without a visible Hero the page template emits a title H1. Disabled sections are absent from HTML. Row IDs remain native stable IDs; no content migration or schema-version rewrite is performed.

The three `smk_block_*` source fieldsets import the shared `smk_section` with explicit type-specific enum/default overrides. The native Revealer opens flat appearance controls without inventing nested layout data: Hero at most anchor/theme/width/spacing, Rich Text anchor/spacing, CTA anchor/theme/spacing. Fixed values are hidden, `always_save` preserves existing settings when the revealer is closed. CP appearance/edit/save/Live Preview remains subject to a separate logged-in acceptance; backend tests are not a substitute.

The Core manifest declares the three block definitions/views, shared fieldsets and the existing assets container. `SectionRegistry::TYPES` is the live developer-owned allowlist, tested against the Core manifest. The renderer receives a view model, not a partial path or CSS class from CMS. Plain text is escaped; validated ProseMirror data is rendered once by native Bard with Antlers disabled. Only paragraphs, H2/H3, lists, bold/italic and safe links are allowed. The native EntrySaving listener validates the complete row list before native persistence, in addition to field validation in CP. Unknown types, missing partials and invalid runtime blocks are omitted with neutral diagnostics; invalid media/link targets are omitted without empty attributes.

`AssetResolver` accepts only local assets-container JPEG/PNG/WebP, valid metadata up to6000px/8MB, resolves alt override → asset alt, honors decorative empty-alt, provides native signed Glide srcset at480/768/1024/1440/1920 capped by source width, never crops/upscales and preserves intrinsic ratio/focal metadata. Hero is the first visible section and its image is the LCP candidate (eager/high); other uses default to lazy/auto. caption/credit are optional. FPM upload limits are unchanged; fixture integration does not close upload acceptance.

`public/assets/demo/core-composition.png` is an original procedural local fixture generated by `tests/Fixtures/Smk/create-demo-image.py` using Python stdlib. It contains no external or client imagery and follows the project's existing license policy. It is not an upload through CP.

The checked-in `smk_page_builder.yaml` is a reviewed compilation artifact from the C10.5 compiler's read-only plan in an isolated input root. Only its declared fieldset bytes were integrated in C10.6. No initializer apply ran on the workbench, and no active profile.json, render-map.json, module imports or smk-init-state ledger were created there. The explicit PHP Core registry is usable for this scoped workbench integration independently of profile activation. A future initializer apply must still refuse unknown/unowned pre-existing generated artifacts; activating/adopting a workbench generation requires its own reviewed authorization, not silently fabricated ownership history.

The compiler now includes the native max20/nullable array rules in its fieldset output. Existing initializer/recovery tests normalize their temporary transaction fixtures to empty Core declarations, so their safety assertions remain independent of the evolving workbench section sources. No assertions or recovery cases were removed.

`document_language` is optional pl/en page metadata; an empty value inherits the site locale. Demo uses pl while the preserved English Home keeps its existing locale fallback. No global site/Herd/environment setting changes were required.
