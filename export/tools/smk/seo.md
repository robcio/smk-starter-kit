# Core SEO (C10.7)

`SeoResolver` owns title/description/robots/canonical/social data. `RenderSeo` fills the fixed `<!-- smk:seo -->` head slot after Statamic creates the response. `ResponseCreated` provides the native Entry; final HTTP status and Content-Type take precedence. The Laravel exception finalizer invokes the same idempotent renderer for responses which bypass the middleware return path. No authorization, publication, redirect or status decision is changed.

Only public, published, unprotected `pages` HTML200 gets public metadata. Preview/token contexts use generic Preview, noindex/nofollow, no canonical/OG/Twitter and private/no-store. HTML errors get generic status titles and noindex; native fragments without head retain their body and receive X-Robots-Tag. Redirects,204/304,JSON/XML get no SEO document head. Error/preview cache headers remain restrictive even without HTML.

Trusted origin is existing config `app.url` (APP_URL), never Host/Forwarded. Workbench: HTTP `.test` in local environment, forced noindex. Production requires explicit HTTPS and refuses local/test/IP origins. Subdirectory deployments fail closed pending route/base-path policy. No primary production origin is activated by this implementation. IDN/punycode is rejected until a separately reviewed origin/validation policy exists; no DNS/network validation occurs.

Pages has an empty semantic query allowlist. Names are URL-decoded, ASCII-lowercased and checked as alphanumeric/underscore. `utm_*`,gclid,dclid,fbclid,msclkid are tracking and discarded. Unknown/array/duplicate names suppress canonical and force noindex; no redirects or guessed semantic normalization. A later module must provide an explicit route policy before introducing pagination/filter identity. Canonical overrides are same-origin absolute HTTP(S), ordinary ports only, no credentials/fragment/controls. Native EntrySaving validates them before persistence; unknown override query is refused. Invalid runtime overrides fall back to self only for an unambiguous representation.

Title: seo_title → page title → site_name; append title_suffix once using ` — `. Description: seo_description → default_description, otherwise omit. No automatic Bard excerpt. Social data uses that model. Image: seo_image → default_og_image, resolved via the shared local Asset/Glide contract, requiring informative alt; unavailable/decorative sources fall through. No image gives summary; valid image gives summary_large_image. A missing description/image never emits empty metadata. Values are encoded by the single Antlers SEO partial.

No sitemap, JSON-LD, analytics, DNS/HTTP fetching of overrides or cross-domain exceptions. Existing physical robots.txt is untouched and requires a separate deployment decision; noindex is not access protection or a ranking guarantee. Static caching is disabled in the workbench. Any future external full-page cache must preserve final metadata context and preview/error no-store; it is not configured here.

Tests use native DataResponse/EntrySaving/token preview and kernel HTTP with in-memory repository I/O. No test content is written to the product. CP/upload/VoiceOver remain separate MVP acceptance items.
